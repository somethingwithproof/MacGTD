**MacGTD є набором робочих процесів для macOS, що дають змогу фіксувати завдання, упорядковувати нагадування та проводити фокус-сесії за таймером у програмах, якими ви вже користуєтеся.**

Створений на основі методології [Getting Things Done](https://gettingthingsdone.com/), цей інструмент додає діалогове, пакетне захоплення та захоплення з буфера обміну до Apple Reminders, фіксацію подій до Calendar, а також команди для завдань, нотаток, проєктів і фокус-сесій до Alfred. AppleScript та Automator забезпечують тісну інтеграцію нативних робочих процесів із macOS. Адаптери API використовують Todoist API v1, Notion API 2026-03-11, Microsoft Graph v1.0 та Google Keep v1. Також включено адаптери для Things і OmniFocus. Тести в хмарному середовищі перевіряють адаптери API на локальній HTTPS-заглушці; для перевірки сумісності в реальних умовах усе ще потрібні окремі облікові записи відповідних постачальників.

## Можливості

- **Фіксуйте завдання без перемикання між програмами.** Використовуйте службу Automator, ключове слово Alfred або буфер обміну, щоб додати завдання. Пакетне захоплення створює одне нагадування для кожного непорожнього рядка.
- **Перетворюйте текст на структуровані завдання.** Розпізнавайте відносні дати та дати у форматі ISO, час, пріоритети, контексти й проєкти за допомогою робочого парсера AppleScript, спільного для нативного швидкого захоплення та захоплення подій у Calendar.
- **Фіксуйте події та переглядайте вхідні.** Створюйте події Calendar із зазначенням часу, тривалості й місця; проводьте п'ятиетапний щотижневий огляд із вивантаженням думок у Reminders.
- **Працюйте у фокус-сесіях за таймером.** Запускайте, перевіряйте та зупиняйте сесії між різними процесами. Власні таймери launchd для кожної сесії відповідають за завершення часу та скасування, а журнали JSONL надають аналітику тривалості.
- **Використовуйте Alfred не лише для завдань.** Створюйте списки Reminders для проєктів, зберігайте довідкові нотатки, відкривайте вхідні для перегляду, захоплюйте текст із буфера обміну та редагуйте типізовані налаштування.
- **Переглядайте вхідні з рядка меню.** Необов'язковий плагін SwiftBar/xbar показує кількість незавершених завдань у вхідних і надає посилання на робочі процеси захоплення.

Нативна поведінка перевіряється на реальних Mac, розміщених на GitHub: тести керують діалогами Automator, а потім зчитують створені записи з Reminders і Calendar. Докладніше про обсяг цієї перевірки дивіться в розділі [тестування та сумісності](#testing-and-compatibility).

## Швидкий старт: Apple Reminders

```bash
git clone https://github.com/somethingwithproof/MacGTD.git
cd MacGTD
open workflows/apple/GTD-QuickCapture.workflow
```

Відкрийте робочий процес в Automator і запустіть його, щоб спробувати захоплення. Щоб зробити його доступним як службу (Service), встановіть пакет у каталозі `~/Library/Services`:

```bash
mkdir -p ~/Library/Services
cp -R workflows/apple/GTD-QuickCapture.workflow ~/Library/Services/
```

Призначте комбінацію клавіш у розділі **Системні параметри → Клавіатура → Клавіатурні скорочення → Служби**. Надайте дозвіл на автоматизацію для Reminders, коли macOS запитає про це. Введіть:

```text
Buy groceries @errands +shopping !1 due:tomorrow
```

Нативний робочий процес створює нагадування з високим пріоритетом і терміном виконання на завтра, спрямовує його до списку `shopping` та записує контекст. Без маркера проєкту чи контексту швидке захоплення використовує `Inbox`.

## Синтаксис захоплення

Нативний парсер завдань і захоплення завдань в Alfred розпізнають наведені нижче маркери. Адаптери зовнішніх сервісів мають власну підтримку полів і маршрутизації.

| Введення | Значення | Приклад |
| --- | --- | --- |
| `!1`, `!2`, `!3` | Високий, середній або низький пріоритет | `Fix login !1` |
| `today`, `tomorrow`, `next week` | Відносний термін виконання | `Call dentist tomorrow` |
| День тижня або `next weekday` | Термін виконання за днем тижня | `Send report next monday` |
| `due:YYYY-MM-DD` | Явна дата виконання | `Renew membership due:2027-03-15` |
| Час разом із датою | Час виконання | `Call Alex tomorrow at 3pm` |
| `@context` | Маркер контексту | `Buy milk @errands` |
| `+project` | Маршрутизація до проєкту або списку | `Draft outline +website` |

Також підтримуються `due:today` і `due:tomorrow`. У маркерах контексту й проєкту використовуйте літери, цифри, підкреслення або дефіси. Нативне швидке захоплення надає маршрутизації за проєктом вищий пріоритет, ніж за контекстом.

Захоплення подій у Calendar використовує `@` для місця проведення події та приймає тривалість у хвилинах або годинах:

```text
Planning tomorrow 2pm 45m @Conference Room
```

Якщо час або тривалість не вказано явно, захоплення в Calendar використовує 9:00 та тривалість одна година в першому календарі, доступному для запису.

### Alfred

Потрібен Alfred із Powerpack. Зберіть пакет із поточного вихідного коду:

```bash
./scripts/package-alfred.sh
open dist/MacGTD.alfredworkflow
```

Ви також можете завантажити пакет зі сторінки [релізів](https://github.com/somethingwithproof/MacGTD/releases). Пакети релізів відповідають стану коду на момент відповідного тегу; для функцій, доданих у гілку `main` після релізу, потрібне збирання з вихідного коду.

| Ключове слово | Дія |
| --- | --- |
| `task` | Захоплення завдання з розбором дати, контексту, проєкту та пріоритету |
| `note` | Збереження довідкової нотатки в Reminders |
| `project` | Створення списку в Reminders |
| `gtd process` | Відкриття Inbox для перегляду користувачем |
| `clip` | Захоплення тексту з буфера обміну |
| `gtd focus` | Запуск фокус-сесії, перевірка статусу або зупинка |
| `gtd analytics` | Перегляд зафіксованої тривалості фокус-сесій |
| `gtd preferences` | Редагування налаштувань робочого процесу |

```text
task Prepare slides tomorrow @work +presentation !2
gtd focus @work 25
gtd focus status
gtd focus stop
```

Налаштування зберігаються у файлі `~/Library/Preferences/com.alfredgtd.plist`; стан фокус-сесій і журнали містяться в каталозі `~/.gtd`. Налаштування мають вбудовані значення за замовчуванням, перевірку типів, валідований імпорт і атомарний запис. Фокус-сесії не змінюють системних параметрів сповіщень. Обробка вхідних лише відкриває список для перегляду, але не переміщує і не завершує завдання автоматично.

Докладніше дивіться в [посібнику для Alfred](../../../workflows/alfred/README.md) та [документації бібліотеки GTDLib](../../../workflows/alfred/GTDLib.scptd/README.md).

### Зовнішні адаптери захоплення

Усі чотири робочі процеси захоплення через API тестуються в хмарному середовищі E2E за допомогою реальних діалогів Automator і локальної TLS-заглушки. Окремий набір ручних тестів перевіряє реальне збереження даних у постачальників за наявності налаштованих окремих облікових записів. Для Things і OmniFocus потрібен набір тестів інтеграції з ліцензованими настільними програмами.

| Ціль | Механізм | Налаштування / джерело |
| --- | --- | --- |
| Todoist | Захоплення через API | [Робочий процес і налаштування Keychain](../../../workflows/todoist/) |
| Notion | Захоплення через Data Source API | [Робочий процес і налаштування Keychain](../../../workflows/notion/) |
| Things 3 | Схема URL | [Робочий процес](../../../workflows/things/) |
| OmniFocus | AppleScript / схема URL | [Робочий процес](../../../workflows/omnifocus/) |
| Microsoft To Do | Microsoft Graph v1.0 | [Робочий процес](../../../workflows/microsoft/) |
| Google Keep | Workspace Keep API v1 | [Робочий процес](../../../workflows/google/) |

Адаптери API потребують налаштування облікових даних; для Microsoft потрібна делегована авторизація OAuth, а для Google Keep потрібен відповідний доступ до Workspace:

```bash
./workflows/todoist/setup-todoist.sh
./workflows/notion/setup-notion.sh
./workflows/microsoft/setup-microsoft.sh
./workflows/google/setup-google.sh
```

Дивіться [вимоги до налаштування API, міграції та авторизації](../../../workflows/api/README.md). Наявні ідентифікатори баз даних Notion мігрують лише тоді, коли знайдено рівно одне джерело даних. Захоплення для Microsoft і Google використовує API замість недокументованих браузерних скорочень. Токени доступу OAuth потребують оновлення через ваш OAuth-клієнт. Корисне навантаження використовує явні ключі JSON, обмежені за часом HTTPS-запити та підтвердження відповіді. Повідомлення про помилки зберігають деталі збою, приховуючи налаштований токен API. Інформацію про повідомлення щодо вразливостей безпеки дивіться в [SECURITY.md](../../../SECURITY.md).

### Рядок меню та Shortcuts

У [посібнику для рядка меню](../../../workflows/menubar/README.md) описано необов'язковий плагін SwiftBar/xbar. Спочатку встановіть служби Apple, потім налаштуйте каталог плагінів у програмі рядка меню та створіть у ньому посилання на `workflows/menubar/gtd-menubar.sh`.

## Архітектура

Пакети Automator містять вбудований код AppleScript, що дає їм змогу працювати як нативні служби (Services). Alfred пакує скрипти дій і передає введення користувача як аргументи. GTDLib надає спільні нативні операції для Reminders із редагованого вихідного коду AppleScript та скомпільованого пакета скриптів.

- **Єдиний робочий парсер:** `scripts/sync-native-parser.py` вбудовує спільний парсер у Quick Capture та Event Capture; валідація виявляє розбіжності у вихідному коді.
- **Постійний стан фокус-сесій:** окремі запуски спільно використовують стан сесії з власними завданнями launchd та обмеженим обліком витраченого часу.
- **Відтворювані пакети:** пакування щоразу збирає новий архів, а тести порівнюють його вміст із вихідним кодом. Бібліотека має окремий скрипт компіляції.
- **Спостережуваність тестів:** звіти JUnit, журнали команд і перевірені артефакти збірки зберігаються в GitHub Actions протягом 14 днів.

## Тестування та сумісність

| Охоплення | Середовище | Що перевіряється |
| --- | --- | --- |
| Валідація | GitHub-hosted macOS 15 та 26 | Компіляція AppleScript, пакети, робочий парсер, цілі дій, налаштування, стан фокус-сесій, транспорт API із заглушкою та зворотна перевірка пакетів |
| Перевірки безпеки | GitHub-hosted Ubuntu та macOS 15 | CodeQL для Python, ShellCheck та обмежений за часом фазинг Atheris для скомпільованого робочого парсера |
| E2E адаптерів сервісів | GitHub-hosted `macos-15-intel` | Усі чотири робочі діалоги API, транспорт TLS, збереження та зчитування із заглушки, помилки API, скасування та вибір джерела Notion |
| E2E реальних сервісів | Ручний запуск на GitHub-hosted Mac зі спеціальними секретами | Реальне захоплення та зчитування даних у Todoist, Notion, Microsoft і Google; завершується помилкою, якщо облікові записи відсутні |
| Ліцензовані настільні інтеграції | Виділений локальний обліковий запис | Запуск і збереження даних через UI у Things 3, OmniFocus 4 та Alfred |
| Нативні настільні E2E | GitHub-hosted `macos-15-intel` | Реальні діалоги Automator; збережені дані Reminders і Calendar; щотижневий огляд; лічильники меню; скомпільована GTDLib; запаковані нативні дії Alfred; реальне завершення та скасування таймера launchd |
| Додатковий UI Alfred | Виділений локальний обліковий запис, Alfred 5 + Powerpack | Імпорт робочого процесу, виклик за ключовим словом і зчитування нагадувань через ліцензований UI |

У [перевіреному запуску модернізації API](https://github.com/somethingwithproof/MacGTD/actions/runs/37857977916) успішно пройдено **35 тестів валідації на кожній платформі валідації та 26 настільних тестів E2E** без жодних збоїв, помилок або пропусків. Настільне покриття включає 15 нативних тестів і 11 тестів адаптерів сервісів, зокрема перевірку реального тайм-ауту транспорту й тимчасових записів у Keychain. Валідація також виконує перевірку структури репозиторію. Ці результати стосуються нативної поведінки та тестових заглушок сервісів і не підтверджують сумісності з реальними зовнішніми сервісами або ліцензованими програмами. Поточний статус відображається на значках вище.

Запити на злиття (pull requests) і надсилання змін у `main` запускають валідацію, а після неї нативні тести E2E. Робочий процес E2E також запускається щоночі та вручну, включно з детермінованими тестами адаптерів сервісів. Тести з реальними сервісами використовують окремий ручний робочий процес `live-e2e.yml`. Типовий CI використовує одноразові Mac на базі GitHub-hosted, ізольовані заглушки та обмежені підпроцеси; для базового набору тестів не потрібен власний раннер (self-hosted) або облікові дані зовнішніх сервісів. Ручний набір тестів із реальними сервісами потребує окремих секретів постачальників.

Поточний CI не перевіряє раніші версії macOS. Запуски з реальними сервісами потребують окремих секретів і ще не були перевірені. Shortcuts/Siri та ліцензовані настільні програми не входять до стандартного хмарного набору тестів. Тести нативних дій безпосередньо викликають запаковані скрипти Alfred; вони не підтверджують повної сумісності з UI Alfred. Дивіться [налаштування тестів, передумови та покриття](../../../tests/e2e/README.md).

## Локалізація

Інтерфейсні рядки CLI, засобу запуску тестів і рядка меню постачаються 45 локалями (`en`, `de`, `es`, `fr`, `it`, `pt-BR`, `nl`, `ru`, `uk`, `ja`, `ko`, `zh-CN`, `zh-TW`, `ar`, `hi`, `pl`, `tr`, `sv`, `vi`, `id`, `af-ZA`, `am-ET`, `ar-EG`, `ar-MA`, `fr-MA`, `fr-SN`, `ha-NG`, `ig-NG`, `mg-MG`, `rw-RW`, `so-SO`, `sw-KE`, `xh-ZA`, `yo-NG`, `zu-ZA`, `bn`, `fa`, `he`, `mr`, `ta`, `te`, `th`, `ur`, `ms`, `fil`) у каталозі `locales/` за допомогою `scripts/i18n.py` без жодних сторонніх залежностей. Визначення локалі перевіряє `--lang`, далі `LC_ALL`, `LC_MESSAGES` та `LANG`, і за замовчуванням повертається до `en`.

```bash
python3 scripts/i18n.py --lang de menubar.quick_capture
LANG=ja_JP.UTF-8 workflows/menubar/gtd-menubar.sh
```

## Розробка

Установіть [mise](https://mise.jdx.dev/) і використовуйте версію Python, зафіксовану в `.mise.toml`:

```bash
mise install
mise exec -- python tests/run.py validation
./scripts/package-alfred.sh
./scripts/build-gtdlib.sh
```

Валідація записує звіти в каталог `test-results/`, а скрипти збирання зберігають результати в `dist/`. Щоб запустити хмарний набір настільних тестів у гілці `main`:

```bash
gh workflow run e2e.yml --ref main -f test_suite=automator
```

Локальне настільне тестування E2E потребує окремого тестового облікового запису з активним сеансом входу та дозволів, описаних у [посібнику з E2E](../../../tests/e2e/README.md). Скрипт налаштування дозволів для хмарного середовища обмежений одноразовими завданнями GitHub-hosted.

Використовуйте [Conventional Commits](https://www.conventionalcommits.org/) і дотримуйтеся правил із [CONTRIBUTING.md](../../../CONTRIBUTING.md). Останні зміни зафіксовано в [CHANGELOG.md](../../../CHANGELOG.md).

Заходи безпеки, перевірку підписів релізів і решту обмежень Scorecard задокументовано в [оцінці безпеки](../../../docs/security-assessment.md). Робочий процес релізу збирає та засвідчує пакети перед створенням чернетки релізу, включно з підписаним походженням (provenance) у форматі in-toto та пакетами Sigstore, перевіреними за вихідним комітом і посиланням (ref). Нові дані про походження застосовуються до цих збірок робочого процесу, а не до старіших завантажень.
