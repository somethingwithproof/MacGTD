**MacGTD - это набор рабочих процессов macOS для быстрого захвата задач, организации напоминаний и проведения ограниченных по времени фокус-сессий в приложениях, которыми вы уже пользуетесь.**

Построенный на методологии [Getting Things Done](https://gettingthingsdone.com/), он добавляет в Apple Reminders захват через диалоговое окно, буфер обмена и пакетный ввод, в Calendar - создание событий, а в Alfred - команды для работы с задачами, заметками, проектами и фокус-сессиями. AppleScript и Automator обеспечивают тесную интеграцию нативных рабочих процессов с macOS. API-адаптеры используют Todoist API v1, Notion API 2026-03-11, Microsoft Graph v1.0 и Google Keep v1. В комплект также входят адаптеры для Things и OmniFocus. Облачные тесты проверяют API-адаптеры с помощью локальной HTTPS-заглушки; для проверки совместимости в реальной среде по-прежнему требуются отдельные учетные записи провайдеров.

## Возможности

- **Захват задач без переключения между приложениями.** Используйте службу Automator, ключевое слово Alfred или буфер обмена для добавления задачи. Пакетный захват создает по одному напоминанию на каждую непустую строку.
- **Преобразование текста в структурированные задачи.** Разбор относительных дат и дат в формате ISO, времени, приоритетов, контекстов и проектов с помощью единого рабочего парсера на AppleScript, который используется и для нативного быстрого захвата, и для захвата в Calendar.
- **Создание событий и разбор входящих.** Создавайте события в Calendar с указанием времени, длительности и места; проводите пятиэтапный еженедельный обзор с выгрузкой мыслей в Reminders.
- **Работа в фокус-сессиях с таймером.** Запускайте, проверяйте и останавливайте сессии из разных процессов. Таймеры launchd, принадлежащие сессии, обрабатывают истечение времени и отмену, а журналы JSONL обеспечивают аналитику длительности.
- **Расширенное использование Alfred.** Создавайте списки Reminders для проектов, сохраняйте справочные заметки, открывайте папку входящих для разбора, захватывайте текст из буфера обмена и редактируйте типизированные настройки.
- **Просмотр входящих из строки меню.** Необязательный плагин SwiftBar/xbar отображает количество невыполненных задач во входящих и содержит ссылки на рабочие процессы захвата.

Нативное поведение проверяется на реальных компьютерах Mac в среде GitHub: тесты взаимодействуют с диалоговыми окнами Automator, а затем считывают созданные записи из Reminders и Calendar. Подробнее об охвате этих проверок см. в разделе [Тестирование и совместимость](#testing-and-compatibility).

## Быстрый старт: Apple Reminders

```bash
git clone https://github.com/somethingwithproof/MacGTD.git
cd MacGTD
open workflows/apple/GTD-QuickCapture.workflow
```

Откройте рабочий процесс в Automator и запустите его, чтобы протестировать захват. Чтобы сделать его доступным как службу, установите пакет в каталог `~/Library/Services`:

```bash
mkdir -p ~/Library/Services
cp -R workflows/apple/GTD-QuickCapture.workflow ~/Library/Services/
```

Назначьте сочетание клавиш в разделе **Системные настройки → Клавиатура → Сочетания клавиш → Службы**. Разрешите доступ к автоматизации для Reminders при запросе macOS. Введите:

```text
Buy groceries @errands +shopping !1 due:tomorrow
```

Нативный рабочий процесс создаст напоминание с высоким приоритетом и сроком на завтра, направит его в список `shopping` и запишет контекст. Если маркер проекта или контекста не указан, быстрый захват использует `Inbox`.

## Синтаксис захвата

Нативный парсер задач и модуль захвата задач Alfred распознают следующие маркеры. Адаптеры провайдеров имеют собственную поддержку полей и маршрутизации.

| Ввод | Значение | Пример |
| --- | --- | --- |
| `!1`, `!2`, `!3` | Высокий, средний или низкий приоритет | `Fix login !1` |
| `today`, `tomorrow`, `next week` | Относительный срок выполнения | `Call dentist tomorrow` |
| День недели или `next weekday` | Срок выполнения на день недели | `Send report next monday` |
| `due:YYYY-MM-DD` | Явно заданная дата срока | `Renew membership due:2027-03-15` |
| Время рядом с датой | Время выполнения | `Call Alex tomorrow at 3pm` |
| `@context` | Маркер контекста | `Buy milk @errands` |
| `+project` | Маршрутизация в проект/список | `Draft outline +website` |

Также поддерживаются `due:today` и `due:tomorrow`. В маркерах контекста и проекта используйте буквы, цифры, символы подчеркивания или дефисы. В нативном быстром захвате маршрутизация по проекту имеет приоритет над маршрутизацией по контексту.

Захват событий Calendar использует `@` для указания места проведения и принимает длительность в минутах или часах:

```text
Planning tomorrow 2pm 45m @Conference Room
```

Если время или длительность не указаны явно, захват Calendar использует 9:00 утра и длительность в один час в первом доступном для записи календаре.

### Alfred

Требуется Alfred с Powerpack. Соберите пакет из текущих исходников:

```bash
./scripts/package-alfred.sh
open dist/MacGTD.alfredworkflow
```

Вы также можете скачать пакет со страницы [релизов](https://github.com/somethingwithproof/MacGTD/releases). Релизные пакеты соответствуют коду на момент создания тега; функции, добавленные в `main` после релиза, требуют сборки из исходников.

| Ключевое слово | Действие |
| --- | --- |
| `task` | Захват задачи с разбором даты, контекста, проекта и приоритета |
| `note` | Сохранение справочной заметки в Reminders |
| `project` | Создание списка в Reminders |
| `gtd process` | Открытие списка входящих для ручного разбора |
| `clip` | Захват текста из буфера обмена |
| `gtd focus` | Запуск фокус-сессии, проверка статуса или остановка |
| `gtd analytics` | Просмотр записанной статистики длительности фокус-сессий |
| `gtd preferences` | Редактирование настроек рабочего процесса |

```text
task Prepare slides tomorrow @work +presentation !2
gtd focus @work 25
gtd focus status
gtd focus stop
```

Настройки хранятся в `~/Library/Preferences/com.alfredgtd.plist`; состояние фокус-сессий и журналы размещаются в `~/.gtd`. Для настроек предусмотрены значения по умолчанию, проверка типов, валидация при импорте и атомарная запись. Фокус-сессии не изменяют системные параметры уведомлений. Обработка входящих открывает список для просмотра и не перемещает и не завершает задачи автоматически.

См. [руководство по Alfred](../../../workflows/alfred/README.md) и [документацию библиотеки GTDLib](../../../workflows/alfred/GTDLib.scptd/README.md).

### Внешние адаптеры захвата

Все четыре рабочих процесса захвата через API проверяются в облачных E2E-тестах с использованием реальных диалоговых окон Automator и локальной TLS-заглушки. Отдельный ручной набор тестов проверяет сохранение данных у реальных поставщиков при наличии настроенных выделенных учетных записей. Для Things и OmniFocus требуется набор интеграционных тестов с лицензированными настольными приложениями.

| Целевой сервис | Механизм | Настройка / исходники |
| --- | --- | --- |
| Todoist | Захват через API | [Рабочий процесс и настройка Keychain](../../../workflows/todoist/) |
| Notion | Захват через API источников данных | [Рабочий процесс и настройка Keychain](../../../workflows/notion/) |
| Things 3 | URL-схема | [Рабочий процесс](../../../workflows/things/) |
| OmniFocus | AppleScript / URL-схема | [Рабочий процесс](../../../workflows/omnifocus/) |
| Microsoft To Do | Microsoft Graph v1.0 | [Рабочий процесс](../../../workflows/microsoft/) |
| Google Keep | Workspace Keep API v1 | [Рабочий процесс](../../../workflows/google/) |

API-адаптеры требуют настройки учетных данных; для Microsoft необходима делегированная авторизация OAuth, а для Google Keep - соответствующий доступ Workspace:

```bash
./workflows/todoist/setup-todoist.sh
./workflows/notion/setup-notion.sh
./workflows/microsoft/setup-microsoft.sh
./workflows/google/setup-google.sh
```

См. [требования к настройке API, миграции и авторизации](../../../workflows/api/README.md). Существующие идентификаторы баз данных Notion переносятся только в том случае, если обнаружен ровно один источник данных. Захват в Microsoft и Google использует API вместо недокументированных браузерных сокращений. Токены доступа OAuth требуют обновления через ваш клиент OAuth. Полезная нагрузка использует явные ключи JSON, ограниченные HTTPS-запросы и подтверждение ответа. Сообщения об ошибках сохраняют подробности сбоя, но скрывают настроенный токен API. Порядок сообщения об уязвимостях описан в [SECURITY.md](../../../SECURITY.md).

## Архитектура

Пакеты Automator содержат встроенный код AppleScript, что позволяет запускать их как нативные службы. Alfred упаковывает скрипты действий и передает пользовательский ввод в виде аргументов. Библиотека GTDLib предоставляет общие нативные операции с Reminders из редактируемого исходного кода AppleScript и скомпилированного пакета скриптов.

- **Единый рабочий парсер:** `scripts/sync-native-parser.py` встраивает общий парсер в Quick Capture и Event Capture; валидация выявляет расхождения с исходным кодом.
- **Сохраняемое состояние фокуса:** отдельные вызовы разделяют общее состояние сессии с принадлежащими ей задачами launchd и ограниченным учетом затраченного времени.
- **Воспроизводимые пакеты:** сборка каждый раз создает свежий архив, а тесты сверяют его содержимое с исходниками. Для компиляции библиотеки предусмотрен отдельный скрипт.
- **Наблюдаемые тесты:** отчеты JUnit, журналы команд и протестированные артефакты сборки хранятся в GitHub Actions в течение 14 дней.

## Тестирование и совместимость

| Область | Среда | Что проверяется |
| --- | --- | --- |
| Валидация | Облачные раннеры GitHub с macOS 15 и 26 | Компиляция AppleScript, пакеты, рабочий парсер, цели действий, настройки, состояние фокуса, транспорт API с заглушкой и полные циклы упаковки и распаковки |
| Проверки безопасности | Облачные раннеры GitHub с Ubuntu и macOS 15 | Python CodeQL, ShellCheck и ограниченный фаззинг с помощью Atheris для скомпилированного рабочего парсера |
| E2E адаптеров провайдеров | Облачный раннер GitHub `macos-15-intel` | Все четыре рабочих диалоговых окна API, TLS-транспорт, сохранение и обратное чтение с заглушкой, ошибки API, отмена и выбор источника Notion |
| E2E с реальными провайдерами | Ручной запуск на облачном Mac в GitHub с выделенными секретами | Реальный захват в Todoist, Notion, Microsoft и Google и обратное чтение от провайдеров; завершается ошибкой при отсутствии учетных записей |
| Лицензированные настольные интеграции | Выделенная локальная учетная запись | Вызов через интерфейс и сохранение данных в Things 3, OmniFocus 4 и Alfred |
| Нативные настольные E2E | Облачный раннер GitHub `macos-15-intel` | Реальные диалоги Automator; сохраненные данные Reminders и Calendar; еженедельный обзор; счетчики меню; скомпилированная GTDLib; упакованные нативные действия Alfred; реальное истечение и отмена таймера launchd |
| Необязательный интерфейс Alfred | Выделенная локальная учетная запись, Alfred 5 + Powerpack | Импорт рабочего процесса, вызов по ключевому слову и обратное чтение напоминаний через лицензированный интерфейс |

В [проверенном прогоне модернизации API](https://github.com/somethingwithproof/MacGTD/actions/runs/37857977916) успешно прошли **35 тестов валидации на каждой платформе валидации и 26 настольных E2E-тестов** без сбоев, ошибок и пропусков. Настольное покрытие включает 15 нативных тестов и 11 тестов адаптеров провайдеров, включая проверки фактического тайм-аута транспорта и временных сбоев Keychain. В рамках валидации также выполняются проверки структуры репозитория. Эти результаты охватывают нативное поведение и заглушки провайдеров, но не подтверждают совместимость с реальными сервисами или лицензированными приложениями. Текущий статус отображается на значках выше.

Pull-реквесты и отправки изменений в `main` запускают валидацию с последующим нативным E2E-тестированием. Рабочий процесс E2E также запускается каждую ночь и вручную, включая детерминированные тесты адаптеров провайдеров. Тесты с реальными поставщиками используют отдельный ручной рабочий процесс `live-e2e.yml`. Стандартный CI использует одноразовые облачные Mac-раннеры GitHub, изолированные заглушки и ограниченные подпроцессы; для базового набора не требуются собственные раннеры или учетные данные внешних сервисов. Ручной набор тестов с реальными сервисами требует выделенных секретов провайдеров.

Более ранние версии macOS в текущем CI не проверяются. Запуски с реальными провайдерами требуют выделенных секретов и пока не подтверждены. Shortcuts/Siri и лицензированные настольные приложения не входят в стандартный облачный набор тестов. Тесты нативных действий вызывают упакованные скрипты Alfred напрямую и не подтверждают полную совместимость с интерфейсом Alfred. См. [настройку тестов, предварительные требования и покрытие](../../../tests/e2e/README.md).

## Локализация

Пользовательские строки интерфейса командной строки, модуля запуска тестов и строки меню поставляются на 45 языках (`en`, `de`, `es`, `fr`, `it`, `pt-BR`, `nl`, `ru`, `uk`, `ja`, `ko`, `zh-CN`, `zh-TW`, `ar`, `hi`, `pl`, `tr`, `sv`, `vi`, `id`, `af-ZA`, `am-ET`, `ar-EG`, `ar-MA`, `fr-MA`, `fr-SN`, `ha-NG`, `ig-NG`, `mg-MG`, `rw-RW`, `so-SO`, `sw-KE`, `xh-ZA`, `yo-NG`, `zu-ZA`, `bn`, `fa`, `he`, `mr`, `ta`, `te`, `th`, `ur`, `ms`, `fil`) в каталоге `locales/` через `scripts/i18n.py` без сторонних зависимостей. При определении локали сначала проверяется `--lang`, затем `LC_ALL`, `LC_MESSAGES` и `LANG` с откатом к `en`.

```bash
python3 scripts/i18n.py --lang de menubar.quick_capture
LANG=ja_JP.UTF-8 workflows/menubar/gtd-menubar.sh
```

## Разработка

Установите [mise](https://mise.jdx.dev/) и используйте версию Python, зафиксированную в `.mise.toml`:

```bash
mise install
mise exec -- python tests/run.py validation
./scripts/package-alfred.sh
./scripts/build-gtdlib.sh
```

Валидация сохраняет отчеты в `test-results/`, а скрипты сборки записывают результат в `dist/`. Чтобы запустить облачный настольный набор тестов на ветке `main`:

```bash
gh workflow run e2e.yml --ref main -f test_suite=automator
```

Для локального запуска настольных E2E-тестов требуется выделенная тестовая учетная запись с выполненным входом в систему и разрешениями, описанными в [руководстве по E2E](../../../tests/e2e/README.md). Облачный скрипт настройки разрешений предназначен только для одноразовых задач в среде GitHub.

Используйте [Conventional Commits](https://www.conventionalcommits.org/) и следуйте [CONTRIBUTING.md](../../../CONTRIBUTING.md). Недавние изменения зафиксированы в [CHANGELOG.md](../../../CHANGELOG.md).

Меры безопасности, проверка подписей релизов и оставшиеся ограничения Scorecard описаны в [оценке безопасности](../../../docs/security-assessment.md). Рабочий процесс релиза собирает и аттестует пакеты перед созданием черновика релиза, включая подписанные данные о происхождении in-toto и пакеты Sigstore, проверенные по исходному коммиту и ссылке ref. Новые данные о происхождении относятся только к этим сборкам рабочего процесса, а не к более ранним загрузкам.
